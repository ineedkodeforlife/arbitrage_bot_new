# Состояние проекта и как продолжить

Документ для продолжения работы с другого устройства. Что умеет сканер и как его
запускать — в [README.md](README.md); здесь — что уже выяснено, почему сделано
именно так и что осталось.

## Что сделано

1. **Парсер прематч- и лайв-линии BC Game** — `arb/bcgame.py`.
2. **Парсер спортивных рынков Polymarket** (список игр + стаканы) — `arb/polymarket.py`.
3. **Сопоставление событий** двух площадок по названиям и времени — `arb/match.py`.
4. **Расчёт вилок** с комиссией Polymarket и глубиной стакана — `arb/calc.py`.
5. **Сканер** с циклом, CSV, звуком и страницей в браузере — `scan.py`, `arb/web.py`.

Зависимостей нет: только стандартная библиотека Python 3.10+ и системный `curl`.
Готового открытого парсера BC Game на GitHub найти не удалось, всё написано с нуля.

## Быстрый старт на новом устройстве

```bash
git clone <адрес репозитория>
cd arb-scanner
python scan.py --hours 24 --near 5
```

Лайв со звуком и страницей (`http://localhost:8765`):

```bash
python scan.py --live --loop 0 --min-profit 1 --sound --web
```

Нужен `curl` в PATH (в Windows 10/11 есть из коробки, на Linux/macOS тоже).
Звук через `winsound` работает только в Windows, на других системах — терминальный
сигнал; звук на странице в браузере работает везде.

## Что выяснено про BC Game

- Спортбук — движок **Betby**. Линия отдаётся GET-запросами без авторизации с хоста
  `api-k-c7818b61-623.sptpub.com`, brand_id `2103509236163162112` (константы `API`
  и `BRAND` в `arb/bcgame.py`). Если перестанет работать — актуальные значения видны
  в сетевых запросах страницы `bc.game/sports` (запросы к `sptpub.com`).
- Адрес: `/api/v4/{prematch|live}/brand/{BRAND}/en/{version}`.
  - `version = 0` — манифест: списки `top_events_versions` и `rest_events_versions`.
  - Каждая версия из манифеста — часть полного снимка (события с основными рынками).
  - Поле `version` в последнем полученном ответе — это адрес следующего запроса,
    который вернёт **только изменения**. Так обновляется сама страница сайта.
    Сервер выпускает изменения раз в ~2 с; полный снимок пересобирается раз в 30 с.
  - Если в ответе поменялся `epoch` — надо перекачать снимок заново.
- Формат изменений (выведен из наблюдений, документации нет): событие приходит
  частично; рынок (`markets[id]`) заменяется целиком; `null` вместо события —
  событие снято. Исход с `"b": 1` заблокирован, коэффициент `"0.0"` — недоступен.
- Нумерация рынков и исходов — как у Sportradar: 1 = 1X2 (исходы 1/2/3),
  10 = двойной шанс (9/10/11), 18 = тотал (12 больше / 13 меньше), 16 = фора
  (1714/1715), 186 = победитель, 219/225/223 = победитель/тотал/фора с овертаймом,
  406 = хоккей с ОТ и буллитами, 251/258/256 = бейсбол, 340 = крикет (4/5 — команды).
  Названия всех рынков: `/api/v3/descriptions/brand/{BRAND}/markets/en`.
- В снимке только основные рынки матча. Полная роспись, судя по запросам страницы,
  лежит в `/api/v4/prematch/brand/{BRAND}/event/en/{event_id}` — не использовалась.
- **Важно: зависание из Python.** При подключении из Python (`http.client`, `urllib`)
  ответы больше 16 КБ с этого хоста замирали ровно после 16 384 байт, при любых
  заголовках и версиях TLS; `curl` и браузер читали нормально. Похоже на сетевую
  фильтрацию по типу TLS-клиента на стороне провайдера, а не на защиту сайта.
  Поэтому все запросы к BC Game идут через `curl` (`arb/http.py: curl_json`), это
  ~230 мс на запрос. На другом устройстве или в другой сети проблемы может не быть —
  тогда `curl_json` можно заменить на `fetch_json` (постоянное соединение, ~50 мс).
  Вариант с библиотекой, подделывающей отпечаток браузера, сознательно не использован.

## Что выяснено про Polymarket

- Ключи не нужны. Список игр: `gamma-api.polymarket.com/events` с параметрами
  `tag_id=100639` (тег «Games»), `active=true&closed=false`,
  `order=startTime&ascending=true&start_time_min=<ISO>`, пагинация `limit/offset`.
  Параметр `end_date_min` вместе с этим тегом возвращает не то, а `live=true` —
  давно приостановленные матчи, поэтому лайв берётся как «началось за последние
  5 часов, `live=true`, период не SUS/PPD/CAN».
- Ответы тяжёлые (~90 КБ на событие), поэтому список обновляется в фоне, а на
  каждом проходе запрашиваются только стаканы: `POST clob.polymarket.com/books`
  с телом `[{"token_id": ...}]`, пачками по 100.
- Нужные рынки: `sportsMarketType` = `moneyline`, `totals`, `spreads`.
  В футболе moneyline — три отдельных рынка «Да/Нет» (победа 1, ничья, победа 2);
  тоталы и форы футбола лежат в дочернем событии «More Markets» (`parentEventId`).
- Комиссия тейкера: `shares × rate × p × (1 − p)`, для спорта `rate = 0.05`
  (берётся из `feeSchedule.rate` рынка). Мейкеры комиссию не платят.
- Вид спорта определяется по слагам тегов события, запасной вариант — префикс слага.

## Замеры

- Проход в лайве ~0,3 с (BC ~240 мс, стаканы ~80 мс), в прематче ~0,6 с.
- В прематче на горизонте 24 ч сопоставляется ~290–310 матчей, ~3000 связок.
  Типичная связка −4…−6 %; вилки встречаются единичные, 0,3–3 %, объём $20–40.

## Что не сделано и не проверено

- Найденные вилки не проверялись руками на сайтах: принимает ли BC Game ставку
  по этому коэффициенту и на эту сумму — неизвестно.
- Ссылки на матчи BC Game собраны по шаблону Betby (`?bt-path=/...`), не открывались.
- Всплывающее уведомление браузера и звук не проверены вживую (кнопка «Проверить»
  на странице показывает, как это выглядит).
- Автоматической простановки ставок нет — только поиск.
- Женские/молодёжные команды с теми же названиями изредка могут сопоставиться
  с основными. Часть событий остаётся без пары (настольный теннис, парный теннис,
  часть баскетбола) — в основном потому, что их нет в снимке BC Game.

## Идеи для продолжения

- Стаканы Polymarket через WebSocket (`wss://ws-subscriptions-clob.polymarket.com/ws/market`)
  вместо опроса — уберёт ~80–400 мс, но нужна библиотека `websockets`.
- Запрашивать стаканы параллельно с запросом линии BC Game (сейчас последовательно).
- Полная роспись рынков BC Game по событию (угловые, тоталы по периодам и т.д.).
- Словарь алиасов команд для несопоставленных событий (`--verbose` показывает,
  сколько событий Polymarket осталось без пары по видам спорта).
- Журнал «жизни» вилки: сколько секунд она держалась — чтобы оценить, успевает ли
  человек её проставить.
