# Состояние проекта и как продолжить

Документ для продолжения работы с другого устройства. Что умеет сканер и как его
запускать — в [README.md](README.md); здесь — что уже выяснено, почему сделано
именно так и что осталось.

## Что сделано

1. **Поток линии BC Game** (прематч и лайв, long-poll) — `arb/bcgame.py`.
2. **Список игр Polymarket** — `arb/polymarket.py`; **стаканы** по WebSocket и HTTP —
   `arb/books.py`; клиент WebSocket на стандартной библиотеке — `arb/ws.py`.
3. **Сопоставление событий** по названиям и времени — `arb/match.py`; единые названия
   видов спорта и киберспортивных дисциплин — `arb/sports.py`.
4. **Расчёт вилок** с комиссией Polymarket и глубиной стакана — `arb/calc.py`.
5. **Движок** — `arb/engine.py`: держит всё в памяти и пересчитывает связки по
   событию; ведёт «жизнь» каждой вилки (появилась, держалась, максимум).
6. **Запуск и вывод** — `scan.py`, `arb/view.py`, страница в браузере `arb/web.py`.
7. **Удобство ручной простановки:** фильтр по времени жизни (`--hold`), калькулятор
   и скрытие на странице (`hidden.json`), Telegram — `arb/notify.py`.
8. **Тесты без сети** — `tests/test_core.py`.

Зависимостей нет: только стандартная библиотека Python 3.10+.

## Быстрый старт на новом устройстве

```bash
git clone <адрес репозитория>
cd arbitrage_bot_new
python scan.py --hours 24 --near 5
```

Непрерывно, со звуком и страницей (`http://localhost:8765`):

```bash
python scan.py --watch --min-profit 1 --sound --web
```

Звук через `winsound` работает только в Windows, на других системах — терминальный
сигнал; звук на странице в браузере работает везде.

## Что выяснено про BC Game

- Спортбук — движок **Betby**. Линия отдаётся GET-запросами без авторизации с хоста
  `api-k-c7818b61-623.sptpub.com`, brand_id `2103509236163162112` (константы `API`
  и `BRAND` в `arb/bcgame.py`). Если перестанет работать — актуальные значения видны
  в сетевых запросах страницы `bc.game/sports` (запросы к `sptpub.com`).
- Адрес: `/api/v4/{prematch|live}/brand/{BRAND}/en/{version}`.
  - `version = 0` — манифест: списки `top_events_versions` и `rest_events_versions`.
  - Каждая версия из манифеста — часть полного снимка (события с основными рынками).
  - Поле `version` в последнем полученном ответе — это адрес следующего запроса,
    который вернёт **только изменения**. Так обновляется сама страница сайта.
    Сервер выпускает версию раз в секунду; полный снимок пересобирается раз в 30 с.
  - Если в ответе поменялся `epoch` — надо перекачать снимок заново.
- Формат изменений (выведен из наблюдений, документации нет): событие приходит
  частично; рынок (`markets[id]`) заменяется целиком; `null` вместо события —
  событие снято. Исход с `"b": 1` заблокирован, коэффициент `"0.0"` — недоступен.
- Нумерация рынков и исходов — как у Sportradar: 1 = 1X2 (исходы 1/2/3),
  10 = двойной шанс (9/10/11), 18 = тотал (12 больше / 13 меньше), 16 = фора
  (1714/1715), 186 = победитель, 219/225/223 = победитель/тотал/фора с овертаймом,
  406 = хоккей с ОТ и буллитами, 251/258/256 = бейсбол, 340 = крикет (4/5 — команды).
  Названия всех рынков: `/api/v3/descriptions/brand/{BRAND}/markets/en`.
- В снимке только основные рынки матча. Полная роспись, судя по запросам страницы,
  лежит в `/api/v4/prematch/brand/{BRAND}/event/en/{event_id}` — не использовалась.
- **Поток изменений.** Версия = удвоенное время в миллисекундах, шаг — 1 секунда.
  Ответы кэшируются на CDN (CloudFront, 30 с), поэтому после снимка надо быстро
  пройти цепочку версий до текущего момента (`Feed.catch_up`). Запрос самой свежей
  версии сервер держит открытым ~1 с, пока она не будет готова, — это и есть
  long-poll. Поле `generated` в ответе — время сервера; по нему считается отставание.
- **Важно: обрыв после 16 КБ и прокси.** При прямом подключении из этой сети ответы
  больше 16 КБ замирали ровно после 16 384 байт. Причина нашлась: `curl` ходил через
  локальный HTTP-прокси из `HTTPS_PROXY` (127.0.0.1:10809), а `http.client` — мимо
  него, и прямое соединение режется где-то по дороге. Теперь `arb/http.py` умеет
  туннель CONNECT через прокси с постоянным соединением (35–60 мс на запрос вместо
  ~350 мс у `curl`). Порядок попыток в `bcgame._choose_transport`: прокси → напрямую
  → `curl`. Прокси с паролем и SOCKS не поддерживаются — тогда остаётся `curl`.
- Номера киберспортивных дисциплин Betby нигде не описаны, поэтому дисциплина
  определяется по названию вида спорта из снимка (`Feed.family`, `arb/sports.py`).
  Рынки киберспорта: 186 победитель, 330 победитель карты (`mapnr`), 328 тотал карт,
  327 фора по картам. Теннис: 202 победитель сета (`setnr`), 189 тотал геймов,
  187 фора по геймам, 188 фора по сетам. Футбол: 29 — обе забьют (74 да / 76 нет).
- Настольного тенниса в прематч-снимке нет вовсе, только в лайве.

## Что выяснено про Polymarket

- Ключи не нужны. Список игр: `gamma-api.polymarket.com/events` с параметрами
  `tag_id=100639` (тег «Games»), `active=true&closed=false`,
  `order=startTime&ascending=true&start_time_min=<ISO>`, пагинация `limit/offset`.
  Параметр `end_date_min` вместе с этим тегом возвращает не то, а `live=true` —
  давно приостановленные матчи, поэтому лайв берётся как «началось за последние
  5 часов, `live=true`, период не SUS/PPD/CAN».
- Ответы тяжёлые (~90 КБ на событие), поэтому список обновляется в фоне, страницы
  качаются параллельно по 4. Глубже `offset=2000` API не листает (ошибка 422) —
  при горизонте 48 ч этого хватает.
- Стаканы: `wss://ws-subscriptions-clob.polymarket.com/ws/market`, подписка
  `{"assets_ids": [...], "type": "market"}`, добавление на ходу —
  `{"assets_ids": [...], "operation": "subscribe"}`, раз в 8 с текстовый `PING`.
  Приходят `book` (стакан целиком) и `price_change` (изменение уровня; нужны только
  `side = SELL`). При подписке сразу на тысячи токенов начальные стаканы приходят
  не по всем — поэтому по 400 токенов на соединение, а первое заполнение идёт по
  HTTP (`POST clob.polymarket.com/books`, пачками по 100). Каждая новая вилка
  дополнительно сверяется по HTTP в фоне.
- Киберспорт: заголовок события «Counter-Strike: A vs B (BO3) - Турнир», названия
  команд надёжнее брать из исходов рынка `moneyline`. Рынки: `child_moneyline`
  («Map N Winner» / «Game N Winner»), `totals` («Games Total: O/U 2.5»),
  `map_handicap` («Map Handicap: A (-1.5) vs B (+1.5)», первый исход — команда с
  форой `line`; в вопросе могут стоять сокращения названий).
- Нужные рынки: `sportsMarketType` = `moneyline`, `totals`, `spreads`.
  В футболе moneyline — три отдельных рынка «Да/Нет» (победа 1, ничья, победа 2);
  тоталы и форы футбола лежат в дочернем событии «More Markets» (`parentEventId`).
- Комиссия тейкера: `shares × rate × p × (1 − p)`, для спорта `rate = 0.05`
  (берётся из `feeSchedule.rate` рынка). Мейкеры комиссию не платят.
- Вид спорта определяется по слагам тегов события, запасной вариант — префикс слага.

## Замеры

- Запуск: 12–15 с (почти всё — список игр Polymarket).
- Горизонт 24 ч, прематч + лайв: сопоставляется ~530 матчей, ~17 000 связок
  (до переделки — ~400 матчей и ~5 900 связок).
- Отставание линии BC Game на «голове» потока 0,2–0,6 с; стаканы Polymarket —
  десятки миллисекунд; пересчёт после изменения — сотые доли миллисекунды.
- Первое сопоставление ~2 с, повторные ~0,1 с (кэш сравнения названий).
- В лайве вилки 1–4 % появляются постоянно (чаще всего киберспорт по картам и
  теннис) и живут 1–5 секунд; объём — сотни долларов.

## Что не сделано и не проверено

- Найденные вилки не проверялись руками на сайтах: принимает ли BC Game ставку
  по этому коэффициенту и на эту сумму — неизвестно.
- Ссылки на матчи BC Game собраны по шаблону Betby (`?bt-path=/...`), не открывались.
- Автоматической простановки ставок нет — только поиск.
- Отправка в Telegram с настоящим токеном не проверялась (с неверным токеном запрос
  доходит через прокси и возвращает 401; напрямую из этой сети Telegram недоступен).
- На части рынков Polymarket младших лиг котировки стоят около 0,5 на любой линии
  (похоже на бота-маркетмейкера) — отсюда «вилки» на 15–40 % с пометкой `[!]`.
  Исполняются ли такие заявки на деле — не проверялось.
- Правило «совпала одна команда» иногда связывает разные матчи с похожими
  названиями; такие пары помечаются, но не отбрасываются.
- Без пары остаются в основном события, которых нет в линии BC Game: настольный
  теннис до начала матча, турниры ITF, мелкие киберспортивные лиги.

## Идеи для продолжения

- Полная роспись рынков BC Game по событию
  (`/api/v4/prematch/brand/{BRAND}/event/en/{event_id}`): раунды и тоталы по картам
  в киберспорте, половины и четверти в баскетболе, угловые в футболе — на Polymarket
  эти рынки есть (`round_over_under_game_N`, `first_half_totals` и т.д.).
- Словарь алиасов команд для несопоставленных событий (`--verbose` показывает,
  сколько событий Polymarket осталось без пары по видам спорта).
- Поправка часов по заголовку `Date` ответа сервера, чтобы отставание считалось точно.
- Третья площадка: модель данных (`Event`, ключи исходов) от площадки не зависит.
